# 运行修复报告

时间：2026-05-24T19:03:25+08:00

## 摘要

在进入 Plan 之前，本地实际运行阻塞已修复并重新验证。本次没有修改业务源码。

## 症状

- 仓库推荐命令依赖 `just` 和 `cargo-nextest`，init 时两者缺失。
- `cargo metadata --no-deps --format-version=1` 初次运行时因 pinned Rust 1.93.0 toolchain 同步而超时。
- 通过多余 `--` 误入 Codex 启动路径时暴露本地状态库 migration 故障：`~/.codex/state_5.sqlite` 在 migration 1 返回 `table threads already exists`。
- 仓库 Node 脚本要求 Node `>=22`，但当前 Codex 启动的 shell 中普通 `node` 解析为 `v20.20.0`。

## 根因

- Rust 1.93.0 组件尚未完整安装。
- 本地开发命令依赖未安装。
- 既有 Codex SQLite 状态库已有部分表，但 migration 状态不被当前 runtime 接受。
- 当前进程处在 Volta recursion 环境中，PATH 里 Node 20 image 优先。

## 已应用修复

- 用 `rustup toolchain install 1.93.0 --component rustfmt --component clippy --component rust-src` 安装 pinned Rust toolchain 组件。
- 用 `cargo install --locked just` 安装 `just`。
- 用 `cargo install --locked cargo-nextest` 安装 `cargo-nextest`。
- 用 `cargo build --bin codex` 重新构建主 CLI。
- 备份旧 Codex 状态库文件：
  - `~/.codex/state_5.sqlite.codex-repair-1779620444.0.bak`
  - `~/.codex/state_5.sqlite-wal.codex-repair-1779620444.0.bak`
  - `~/.codex/state_5.sqlite-shm.codex-repair-1779620444.0.bak`
- 随后运行 doctor，让 Codex 重建状态库。
- 安装/验证 Volta Node 22.22.3，并记录当前会话 workaround：`volta run --node 22 ...`。

## 验证结果

- `just --version` -> `just 1.51.0`
- `cargo nextest --version` -> `cargo-nextest 0.9.136`
- `rustup component list --toolchain 1.93.0-x86_64-unknown-linux-gnu --installed` 列出 cargo、clippy、rust-docs、rust-src、rust-std、rustc、rustfmt。
- `cargo metadata --no-deps --format-version=1` 在 `codex-rs/` 下成功。
- `cargo run --bin codex -- --version` -> `codex-cli 0.0.0`
- `just codex --version` -> `codex-cli 0.0.0`
- `just exec --help` 成功。
- `./codex-rs/target/debug/codex doctor --summary` -> `12 ok · 1 idle · 3 notes · 1 warn · 0 fail degraded`.
- `volta run --node 22 node --version` -> `v22.22.3`；当前 Codex 会话中普通 `node --version` 仍为 `v20.20.0`。
